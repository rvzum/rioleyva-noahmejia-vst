# Установщики RIO LEYVA x NOAH MEJIA VST (macOS + Windows)

Пакует Release-сборку плагина в обычный установщик, который кладёт
`RIO LEYVA x NOAH MEJIA VST.vst3` в системную папку VST3 —
`/Library/Audio/Plug-Ins/VST3/` на macOS,
`C:\Program Files\Common Files\VST3\` на Windows — то есть плагин увидят
все пользователи и все DAW на машине, а не только тот, кто ставил.

**По умолчанию установщик также кладёт папку с сэмплами** (банки/one-shot
киты) в системное место, общее для всех пользователей машины — подробности
ниже, в разделе "Сэмплы внутри установщика".

## macOS: как собрать установщик локально

В обычном Terminal.app **на своём Mac** (не через удалённый мост/VM —
`pkgbuild`/`productbuild` существуют только в настоящей macOS):

```bash
cd "~/27wav rioleyva x noahmejia VST"
chmod +x Scripts/build_installer.sh   # один раз
./Scripts/build_installer.sh
```

Результат: `Packaging/build/RIO LEYVA x NOAH MEJIA VST Installer.pkg`.

Скрипт сам:
1. Настраивает и собирает Release-версию плагина в отдельной папке
   `build-release/` (твоя обычная `build/` для разработки не трогается).
2. Собирает только VST3 (без Standalone-приложения — как договорились).
3. Копирует `~/Music/27wav rioleyva & noahmejia banks/` (если она есть и
   не пустая) во временную папку и упаковывает её вторым компонентом.
4. Упаковывает `.vst3` (и, если есть сэмплы, банки) через `pkgbuild` +
   `productbuild` в один `.pkg` с приветственным экраном.

Быстрая пересборка без сэмплов (папка с банками большая, ~2ГБ — удобно
для проверки самого плагина):

```bash
./Scripts/build_installer.sh --no-samples
# или
SKIP_SAMPLES=1 ./Scripts/build_installer.sh
```

Другая папка-источник сэмплов (не `~/Music/...`):

```bash
W27_SAMPLES_DIR="/путь/к/банкам" ./Scripts/build_installer.sh
```

## Windows: установщик собирается только на GitHub Actions

На этом Mac нет Windows, поэтому Windows-установщик (`.exe`, через
[Inno Setup](https://jrsoftware.org/isinfo.php)) собирается исключительно
в облаке — workflow `.github/workflows/build-installers.yml` при каждом
`git push` в `main` пересобирает **оба** установщика (macOS и Windows) на
GitHub-раннерах и публикует их как assets в rolling-релизе `latest` этого
репозитория на GitHub (вкладка **Releases**).

Ничего запускать самому не нужно — просто:

```bash
git push
```

и через несколько минут во вкладке **Actions** появится зелёная галочка,
а в **Releases → latest** — два свежих файла:
`RIO LEYVA x NOAH MEJIA VST Installer.pkg` и
`RIO LEYVA x NOAH MEJIA VST Installer.exe`.

Их и рассылай всем, кому нужно поставить плагин.

## Сэмплы внутри установщика

Плагин теперь ищет банки сэмплов в ДВУХ местах и объединяет их в одно
дерево (см. `SampleLibraryManager::rescan()`):

1. `~/Music/27wav rioleyva & noahmejia banks/` (macOS) /
   `%USERPROFILE%\Music\27wav rioleyva & noahmejia banks\` (Windows) —
   как раньше, личная папка каждого пользователя, куда можно добавлять
   свои киты вручную.
2. **Новое:** `/Library/Application Support/27wav/Sample Banks` (macOS) /
   `C:\ProgramData\27wav\Sample Banks` (Windows) — общая для всей машины
   папка, которую заполняет ТОЛЬКО установщик. Именно сюда оба
   установщика (`.pkg` и `.exe`) кладут банки по умолчанию.

Почему не `~/Music/...` в самом установщике (казалось бы, логичнее): на
Windows у Inno Setup нет надёжного способа узнать "домашнюю папку
реального пользователя" при установке с правами администратора — есть
задокументированный риск, что сэмплы уедут не в тот профиль. Общая
папка для всей машины (`ProgramData` / `Application Support`) не зависит
от того, под каким админом ставили, поэтому она надёжнее и одинаково
работает на обеих платформах.

Компонент с сэмплами включён по умолчанию, но необязателен:
- **macOS**: на экране установщика есть кнопка "Customize" — сэмплы
  можно снять галочкой.
- **Windows**: на экране "Select Components" — то же самое, отдельный
  чекбокс "Sample Banks".

### Как загрузить сэмплы, чтобы CI мог их подхватить

Реальные файлы сэмплов (~2ГБ) физически лежат только на этом Mac — CI на
GitHub их не видит. Поэтому один раз (и потом при каждом изменении
банков) нужно загрузить их как assets отдельного GitHub-релиза с тегом
`samples`, откуда их скачивает `build-installers.yml`:

```bash
brew install gh        # если ещё не стоит
gh auth login           # один раз

cd "~/27wav rioleyva x noahmejia VST"
chmod +x Scripts/upload_samples.sh   # один раз
./Scripts/upload_samples.sh
```

Скрипт сам зазипует каждую папку-кит по отдельности (каждый архив
гарантированно меньше лимита GitHub в 2ГБ на файл) и загрузит их в
релиз `samples` (он не помечен как "последний" и не будет показан как
основной релиз плагина — это просто хранилище для CI).

**Если релиза `samples` ещё нет** — оба установщика всё равно соберутся,
просто без сэмплов (только плагин). Это безопасный запасной вариант,
ничего не сломается.

После загрузки сэмплов сделай `git push` (или запусти workflow вручную
из вкладки Actions → "Build installers" → "Run workflow"), чтобы
пересобрать установщики уже с банками внутри.

## Важно: установщики НЕ подписаны

У тебя нет Apple Developer ID и Windows code-signing сертификата, поэтому
ни `.pkg`, ни `.exe` не подписаны. Это значит: при первом запуске на
чужой машине сработает системная защита —Gatekeeper на macOS,
SmartScreen на Windows — и появится предупреждение о "неизвестном
разработчике". Плагин при этом полностью рабочий, это просто стандартная
защита ОС от неподписанного софта, не баг.

### Что сказать получателям установщика

Перешли им это (или своими словами):

**macOS:**
> При открытии `RIO LEYVA x NOAH MEJIA VST Installer.pkg` macOS покажет предупреждение
> "нельзя открыть, т.к. он от неустановленного разработчика". Это нормально
> для установщика без платной Apple-подписи ($99/год). Чтобы всё равно
> установить:
>
> 1. Откройте **Системные настройки → Конфиденциальность и безопасность**.
> 2. Прокрутите вниз до раздела "Безопасность" — там будет строка про
>    заблокированный `RIO LEYVA x NOAH MEJIA VST Installer.pkg` и кнопка **"Открыть все
>    равно"** ("Open Anyway"). Нажмите её, введите пароль/Touch ID.
> 3. Запустите установщик ещё раз — теперь появится обычное окно с
>    подтверждением, нажмите **"Открыть"**.
>
> (Альтернативный способ: правый клик / Control+клик по файлу `.pkg` →
> "Открыть" — на части версий macOS сработает сразу, без похода в
> настройки.)
>
> Если DAW при первом сканировании плагина тоже покажет похожее
> предупреждение — тот же путь через Системные настройки решает и это.

**Windows:**
> При запуске `RIO LEYVA x NOAH MEJIA VST Installer.exe` Windows покажет синий
> экран SmartScreen "Windows защитила ваш компьютер". Это нормально для
> установщика без платного сертификата подписи кода. Чтобы всё равно
> установить:
>
> 1. Нажмите **"Подробнее"** ("More info").
> 2. Появится кнопка **"Всё равно выполнить"** ("Run anyway") — нажмите
>    её.
> 3. Установщик запросит права администратора (это нужно, чтобы
>    положить плагин в общую папку VST3, доступную всем DAW) —
>    подтвердите.

### Если захочешь убрать эти предупреждения совсем

- **macOS**: Apple Developer Program ($99/год) — получить Developer ID
  Application + Installer сертификаты, подписать `.vst3` и `.pkg`
  (`codesign`), прогнать через нотарификацию Apple (`notarytool`).
- **Windows**: сертификат подписи кода (EV-сертификат от Sectigo,
  DigiCert и т.п., обычно от ~$100-400/год) и подпись `.exe` через
  `signtool`.

После этого установщики будут открываться без единого предупреждения.
Могу подготовить обновлённые скрипты/workflow под это, когда появятся
сертификаты — просто скажи.

## Структура

```
Scripts/
  build_installer.sh          -- сборка + упаковка macOS .pkg (см. выше)
  upload_samples.sh           -- загрузка сэмплов в GitHub-релиз "samples"
                                  для CI (см. выше)
.github/workflows/
  build-installers.yml        -- CI: собирает оба установщика при каждом
                                  push, публикует их в релизе "latest"
Packaging/
  Distribution.xml             -- описание установщика для productbuild,
                                   плагин + сэмплы (плейсхолдеры вида
                                   __VERSION__ подставляются скриптом)
  Distribution-plugin-only.xml -- то же самое, но без компонента сэмплов
                                   (используется при --no-samples)
  windows/
    installer.iss              -- Inno Setup скрипт для Windows-установщика
  Resources/
    Welcome.html                -- текст на первом экране установщика
    Conclusion.html              -- текст на экране "готово"
  build/                        -- сюда попадает итоговый .pkg/.exe при
                                    локальной сборке (не в git)
```

## Версия

Версия установщика берётся из `project(27wavVST VERSION 0.1.0 ...)` в
корневом `CMakeLists.txt` — подними её там перед следующим релизом, оба
скрипта (macOS и Windows) подхватят автоматически.
